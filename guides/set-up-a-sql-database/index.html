What you are building

With SQLite, a database is one file on your computer, such as portfolio.db. Inside it are tables: named grids of rows and columns.

The job: make the file, load the CSV as a table, check the count.

Wondering about MySQL or PostgreSQL? See which SQL database to install.

The steps

1Know your fileLook inside and write down the row count›

A CSV is a plain text file that holds a table: usually one row per line, with commas between values.

  1. Download the practice CSV above, or use your own.
  2. Open it in a text editor.
  3. Check the first line. Ours is date,precipitation,temp_max,temp_min,wind,weather.
  4. Write down how many data rows you expect.

Using your own file? Use your own table and column names in the later steps.

Quick check

Our file has 1,462 lines, and the first is the header. How many data rows should the table have?

2Install DB Browser for SQLiteA free app with SQLite built in›
  1. Go to sqlitebrowser.org/dl. The current release on November 27, 2026 was 3.13.1.
  2. Windows: most PCs use the 64-bit installer. Mac: download the .dmg and drag the app to Applications.
  3. Windows: if the installer asks about shortcuts, keep a Program Menu shortcut for DB Browser (SQLite).
  4. Open the app.

You should see: a window with New Database and Open Database buttons.

3Create the database fileOne new file, still empty›
  1. Click New Database.
  2. Pick your folder, name the file portfolio.db and save.
  3. A window opens to define a table. Click Cancel. The CSV import builds the table for you.

You should see: an empty database with no tables listed yet.

4Import the CSVTwo settings to check, then save›
  1. Choose File › Import › Table from CSV file.
  2. Pick seattle-weather.csv.
  3. In Table name, type weather_raw.
  4. Tick Column names in first line.
  5. Check the preview: the headings should read date, precipitation and so on.
  6. Click OK.
  7. Click Write Changes (Ctrl+S, or Cmd+S on a Mac). Until then, the import is not saved to the file.

Why rename the table? The app fills in the file name, seattle-weather. A hyphen is the minus sign in SQL, so you would have to quote that name in every query. Use underscores. _raw marks the untouched original; do cleaning in a copy.

Importing twice into the same table name adds the rows again. If the app asks whether to import into the existing table, answer No unless you mean to append.

File too big for Excel? See How to Handle Large Datasets.

5Verify with SQLCount first, then look›

Open the Execute SQL tab. Paste one query, then run it with the run button or Ctrl+Return (Cmd+Return on a Mac). Replace it with the next query.

SELECT COUNT(*) AS row_count
FROM weather_raw;
row_count
1461

A match with your expected number is your first check. Then check the date range.

SELECT MIN(date) AS first_date,
       MAX(date) AS last_date,
       COUNT(DISTINCT date) AS date_count
FROM weather_raw;

1,461 different dates in 1,461 rows: no date repeats. Now look at real rows.

SELECT *

To remove a bad table, select it on the Database Structure tab, choose Delete Table, then Write Changes.

Text hiding in a number column

DB Browser guesses each column type from the rows near the top. A later value such as $4.99 or 1,299 can be stored as text. SQLite then returns a wrong total with no error. Try it:

DROP TABLE IF EXISTS price_raw;
CREATE TABLE price_raw (order_id INTEGER, price REAL);
INSERT INTO price_raw VALUES
  (1, '$4.99'), (2, '1,299'), (3, 20);

SELECT SUM(price) AS total
FROM price_raw;
totalWhat it should be
21.01323.99

$4.99 counted as 0 and 1,299 counted as 1. Find the text values:

SELECT order_id, price
FROM price_raw
WHERE typeof(price) = 'text';
order_idprice
1$4.99
21,299

Clean them into a new table and leave the original alone.

DROP TABLE IF EXISTS price_clean;
CREATE TABLE price_clean AS
SELECT order_id,
       CAST(REPLACE(REPLACE(price, '$', ''), ',', '')
            AS REAL) AS price
FROM price_raw;

SELECT SUM(price) AS total
FROM price_clean;
total
1323.99
CAST turns text such as N/A into 0. List the text values and decide what each one means before you convert. This cleanup assumes commas separate thousands.

Choosing and next habits

?Which SQL database should you install?SQLite, DuckDB or a server›

Learning, and the data is yours? Start with a file-based database: SQLite, or DuckDB if you mostly summarize CSV files. There is no server to start or password to set.

File or server?

A file-based database runs inside the program you are using, and the data sits in a file. A server database is a separate program that stays running and answers requests, so it has user accounts and permissions.

SQLite lets several programs read at once, but only one can write at a time. For one learner that is rarely a problem.

DuckDB on a CSV

After pip install duckdb, run this in Python from the folder that holds the file. Set up DuckDB.

import duckdb

duckdb.sql("""
    SELECT weather, COUNT(*) AS day_count
    FROM 'seattle-weather.csv'
    GROUP BY weather
    ORDER BY day_count DESC
""").show()

It lists the same five counts as step 5.

When you need a server

  • An application and people need to write to the same data
  • Colleagues query it from their own computers
  • A hosted tool or dashboard must reach it over a network
  • The job requires a specific product

For analysis work, try PostgreSQL. At a Microsoft workplace you may meet SQL Server.

Does the SQL transfer?

The core does: SELECT, WHERE, JOIN, GROUP BY, HAVING, ORDER BY, subqueries, CTEs, window functions and CASE. Expect differences in date and text functions, type conversion and some syntax. SQL Server uses TOP where SQLite uses LIMIT.

SQLite from Python

import sqlite3

con = sqlite3.connect("analysis.db")
con.execute("DROP TABLE IF EXISTS orders")
con.execute("""CREATE TABLE orders
    (order_id INTEGER, region TEXT, amount INTEGER)""")
con.execute("INSERT INTO orders VALUES (101, 'North', 120)")
con.commit()
query = "SELECT COUNT(*), SUM(amount) FROM orders"
print(con.execute(query).fetchall())
con.close()
It prints
[(1, 120)]

commit() saves the inserted row. With the default settings, closing without it loses the insert. The script rebuilds its orders table on each run, so use it on this practice file.

First five things to do

  1. Load one real file you care about. See loading your first CSV.
  2. Count the rows and compare with the source.
  3. Check the types. Numbers stored as text sort 100 before 20.
  4. Write five questions in plain English, then answer one at a time.
  5. Save your queries in a file with comments.

Keep the data safe

  • Keep raw files in the project folder and never edit them.
  • Back up a SQLite file by copying it after you have saved and closed every program using it.
  • Do not work on a database file from a synced or network folder on two computers.
