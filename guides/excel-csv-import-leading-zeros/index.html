Keep Leading Zeros When Importing a CSV

By Michael Nocito, implementation analyst · Updated November 27, 2026

Excel can turn the ZIP code 08053 into the number 8053 while opening a CSV. Import the file and set label columns to Text to keep what the file says.

The steps

1See what can changeFour kinds of values›

A CSV is plain text. It does not say which column is a number and which is a label. When Excel opens it, its automatic conversions can decide for you.

In the fileExcel can showWhat changes
080538053Leading zero removed
10002000300045671.0002E+15Digits after the 15th become 0
SEPT11-SepText becomes a date
3-22-Mar (US settings)Text becomes a date
123E51.23E+07Text becomes a number

These are default behaviors. Your Excel may be set differently, or may ask before converting. If you save the file after a conversion, the changed values can replace the originals.

This is not only a ZIP code problem. A 2016 scan of genomics papers found gene name errors in about one fifth of those with Excel gene lists (Ziemann, Eren and El-Osta). In 2020 the human gene naming committee renamed affected genes; SEPT1 became SEPTIN1.

3Import with the column type setData, From Text/CSV, Transform Data›

These steps are for Excel for Microsoft 365 on Windows. Names can differ in other versions.

  1. Open a blank workbook. Do not double-click the CSV.
  2. On the ribbon, choose Data, then From Text/CSV. Pick customers.csv.
  3. In the preview window, choose Transform Data. The Power Query Editor opens.
  4. Select zip, then hold Ctrl and select account_number and part_code.
  5. Right-click a selected header, then choose Change Type, then Text.
  6. If Excel asks about the existing type step, choose Replace current.
  7. Check that 08053 shows its zero and the account numbers show all 16 digits. Choose Close & Load.
Replace current matters. Power Query often adds a type step of its own. Adding a second step after it converts the already shortened number to text. Replacing it reads the original text.

The data loads as a table, usually named customers. The query is saved, so you can open it later under Data, Queries & Connections and change the types. More on tables: name your data.

4Check the conversion settingsA second safeguard in newer Excel›

Excel for Microsoft 365 and Excel 2024 let you turn off some automatic conversions (Microsoft Support).

SystemWhere
WindowsFile, Options, Data, Automatic Data Conversion
MacExcel, Preferences, Edit, Automatic Data Conversion

The options cover:

  • removing leading zeros
  • keeping the first 15 digits of long numbers
  • reading digits around an E as scientific notation
  • reading unbroken letters and numbers, such as JAN1, as a date
Limits. Values with spaces or other characters, such as JAN-1, may still become dates, so do not rely on this for 3-2. The settings do not directly affect Power Query imports. They belong to your Excel, so a coworker may get a different result from the same file.

5Check the columnOne formula that counts wrong lengths›

US ZIP codes in this file have 5 characters. In an empty cell outside the table, count the values that do not:

=SUMPRODUCT(--(LEN(customers[zip])<>5))
How the file came inResult
zip imported as Text0
Zeros removed3

Change the table and column names to match yours. This checks length only. It will also count blanks and longer formats such as ZIP+4. For the habit behind it, see check your work.

6Repair a file that is already changedRe-import first, rebuild second›

If the cell holds the number 8053, formatting alone does not put the zero back into the value.

Best: import the original CSV again

Keep the raw file unchanged and work in a copy.

If the width is fixed: rebuild as text

Add a column inside the table:

=TEXT([@zip],"00000")

8053 returns 08053. Use this when you know each value should have exactly 5 digits.

  • An account number of unknown length cannot be rebuilt this way.
  • Digits lost past the 15th cannot be recovered from the cell. Get the source file.
  • For one typed value, start it with an apostrophe: '08053.
