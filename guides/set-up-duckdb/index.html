Set Up DuckDB and Query a CSV

By Michael Nocito, implementation analyst · Updated November 27, 2026

Query a CSV file with SQL without importing it first. In a query, put the file name in quotes where a table name goes, and DuckDB reads the file and works out the column types.

The steps

1Install DuckDBOne command›
python -m pip install duckdb

Run this in a terminal. On a Mac the command may be python3. DuckDB runs inside your Python program, so there is no database server to start and no password to set.

import duckdb

print(duckdb.__version__)

A version number means the install worked.

python -m pip installs into the same Python that python runs. See Install Python for data analysis. If pip reports an externally-managed-environment error, create a virtual environment first.

2Query a CSVNo import step›
import duckdb

duckdb.sql("""
    SELECT Country,
           COUNT(*) AS invoices,
           ROUND(SUM(Total), 2) AS revenue
    FROM 'invoices.csv'
    GROUP BY Country
    ORDER BY revenue DESC
    LIMIT 5
""").show()
Countryinvoicesrevenue
USA91523.06
Canada56303.96
France35195.1
Brazil35190.1
Germany28156.48

FROM 'invoices.csv' reads the file. There is no CREATE TABLE, and this example creates no database file. The printed result also shows each column type under its name.

"No files found that match the pattern" means DuckDB did not find the file. A short path starts from the folder you ran Python in, which may differ from the script's folder.

3Check the column typesRun DESCRIBE on a new file›
import duckdb

duckdb.sql("DESCRIBE SELECT * FROM 'invoices.csv'").show()
column_namecolumn_type
InvoiceIdBIGINT
CountryVARCHAR
InvoiceDateTIMESTAMP
TotalDOUBLE

The full output has four more columns, left out here. BIGINT is a whole number, VARCHAR is text, TIMESTAMP is a date and time, and DOUBLE is a decimal number.

The types are a guess from a sample of the file (the documented default sample is 20,480 rows). Check that IDs and codes are the type you want. A later value that does not fit stops the query:

import duckdb

with open("late.csv", "w") as f:
    f.write("id,code\n")
    for i in range(1, 30001):
        f.write(f"{i},{i}\n")
    f.write("30001,A7\n")

try:
    duckdb.sql("SELECT MAX(code) FROM 'late.csv'").show()
except duckdb.ConversionException as error:
    print(str(error).splitlines()[0])

duckdb.sql("""
    SELECT COUNT(*) AS row_count, MAX(code) AS max_code
    FROM read_csv('late.csv', types = {'code': 'VARCHAR'})
""").show()

The first query reports Conversion Error: CSV Error on Line: 30002. The second names the type and works:

row_countmax_code
30001A7

MAX on text compares characters, so A7 sorts after the digits. Another option is sample_size = -1, which reads the whole file before choosing types.

4Fix numbers stored as textCommas and N/A›

One comma or N/A in a small file can make the whole column text, and SUM then fails.

import duckdb

with open("messy.csv", "w") as f:
    f.write('order_id,amount\n'
            '00041,125.50\n'
            '00042,"1,240.00"\n'
            '00043,N/A\n')

duckdb.sql("""
    SELECT order_id,
           amount,
           TRY_CAST(REPLACE(amount, ',', '') AS DOUBLE)
               AS amount_num
    FROM 'messy.csv'
""").show()
order_idamountamount_num
00041125.50125.5
000421,240.001240.0
00043N/ANULL

REPLACE removes the thousands comma. TRY_CAST returns NULL for a value it cannot convert. Plain CAST stops with an error instead. The IDs kept their leading zeros in this test.

Look at every row that became NULL before you trust a total. This comma rule assumes a comma separates thousands. In files that use a decimal comma, it gives wrong numbers.

5Query a folder of filesOne asterisk›

First, split three months of 2013 into separate files:

import os
import duckdb

os.makedirs("months", exist_ok=True)
for month in ["2013-01", "2013-02", "2013-03"]:
    duckdb.sql(f"""
        COPY (SELECT * FROM 'invoices.csv'
              WHERE strftime(InvoiceDate, '%Y-%m') = '{month}')
        TO 'months/{month}.csv' (HEADER)
    """)

duckdb.sql("""
    SELECT COUNT(*) AS rows_across_files
    FROM 'months/*.csv'
""").show()
rows_across_files
19

The files hold 7, 5 and 7 rows. Add another file with the same columns and the same query includes it.

When columns differ

Here the second file has an extra column:

import os
import duckdb

os.makedirs("shapes", exist_ok=True)
with open("shapes/2013-01.csv", "w") as f:
    f.write("id,amount\n1,10\n2,20\n")
with open("shapes/2013-02.csv", "w") as f:
    f.write("id,amount,channel\n3,30,web\n4,40,store\n")

duckdb.sql("SELECT * FROM 'shapes/*.csv'").show()

duckdb.sql("""
    SELECT * FROM read_csv('shapes/*.csv',
                           union_by_name = true)
""").show()
QueryColumns returned
Plain file patternid, amount
union_by_nameid, amount, channel
The plain query dropped channel without a message in DuckDB 2.0.1 and 1.5.6. The first file here (2013-01.csv) set the columns. When a later file instead lacked one of the first file's columns, the query stopped with a schema mismatch error.

union_by_name = true matches columns by name and fills gaps with NULL. A renamed column shows up as two half-empty columns, so check the column list.

6Use it with pandasResults in, DataFrames out›
python -m pip install pandas
import duckdb

df = duckdb.sql("""
    SELECT Country, COUNT(*) AS n
    FROM 'invoices.csv'
    GROUP BY Country
    ORDER BY n DESC, Country
    LIMIT 3
""").df()
print(df.to_string(index=False))

duckdb.sql("SELECT * FROM df WHERE n > 40").show()
Countryn
USA91
Canada56
Brazil35

.df() returns a pandas DataFrame. The last query reads the DataFrame by its variable name and returns the USA and Canada rows.

A useful split: filter, join and group in SQL, then chart the smaller result in Python. Brazil and France both have 35, so the second sort column makes the top 3 repeatable. More: Connect Python to a database and pandas GroupBy.

7Save your workA CSV or a database file›
import duckdb

duckdb.sql("""
    COPY (SELECT Country, ROUND(SUM(Total), 2) AS revenue
          FROM 'invoices.csv'
          GROUP BY Country
          ORDER BY revenue DESC)
    TO 'revenue_by_country.csv' (HEADER)
""")

con = duckdb.connect("shop.duckdb")
con.sql("""
    CREATE OR REPLACE TABLE invoices AS
    SELECT * FROM 'invoices.csv'
""")
con.sql("SELECT COUNT(*) AS saved_rows FROM invoices").show()
con.close()
saved_rows
412

COPY ... TO writes a result file. duckdb.connect("shop.duckdb") opens a database file that keeps tables between runs. CREATE OR REPLACE overwrites a table with the same name. The saved table is a copy, so it does not change when the CSV changes.

DuckDB or SQLite?

JobStart with
Ask questions of CSV or Parquet filesDuckDB
Summarize many rowsDuckDB
An app making many small writesSQLite
A database file for a tool that reads SQLiteSQLite
Follow an SQL lessonThe one it uses

Both can keep data in a single file and run without a server. DuckDB stores and processes data by column, which suits summaries. SQLite comes with Python. See Which SQL database to install.

!Fix common errorsMessages and causes›
ProblemWhat to try
No files foundCheck the folder you ran Python in, or use a full path
Conversion Error on a CSV lineSet the type with types, or nullstr for text such as N/A
SUM rejects VARCHARFind the text values, then use TRY_CAST
.df() reports a missing moduleInstall pandas in the same Python
Garbled table borders or UnicodeEncodeError on WindowsSet PYTHONIOENCODING to utf-8 in the terminal
Slow or out of memorySelect the columns you need. For repeated queries, save a table or Parquet file

A CSV is still read as text from the file, so naming fewer columns helps less than with Parquet or a DuckDB table.
