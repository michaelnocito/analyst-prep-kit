Handling Missing Values in pandas: dropna, fillna and What Each One Claims

By Michael Nocito, implementation analyst · Updated November 27, 2026

Dropping or filling a hole says something about the value that was there. Count the holes, find out why they exist, then choose.

2Drop rows on purposeA bare dropna() removes 4 of 16 rows›

dropna() removes a row if any column is empty, including columns you do not plan to use. Guess the row counts, then run this.

print(len(df))
print(len(df.dropna()))
print(len(df.dropna(subset=["units"])))
print(len(df.dropna(how="all")))
print(len(df.dropna(thresh=7)))
print(list(df.dropna(axis=1).columns))

3Check what summaries skipcount() shows how many values were used›

sum, mean and std skip empty values by default, with no warning.

print(df["units"].count(), len(df))
print(df["units"].sum())
print(df["units"].mean())
print(df["units"].std())

The honest sentence: average units are 5.29 among the 14 orders with a quantity.

Revenue exists on 13 rows. Its total is 8,150. With no holes, the table totals 9,890, so this sum is 1,740 short.

When skipping is the wrong choice

empty = pd.Series([np.nan, np.nan])
print(empty.sum())
print(empty.sum(min_count=1))
print(df["units"].mean(skipna=False))

These print 0.0, nan and nan. A sum of nothing shows as zero unless you set min_count=1.

Quick check

A column is entirely empty. What does a plain sum() return?

Use zero when you know nothing happened, such as a day confirmed to have no sales. Leave it empty when the value is unknown. The same trap exists in spreadsheets with IFERROR.

pandas 3: df["units"].fillna(0, inplace=True) leaves df unchanged and shows a chained assignment warning. Assign the result: df["units"] = df["units"].fillna(0).

5Fill with the mean with careSame mean, smaller spread›

Filling holes with the column mean keeps the mean the same. Guess what changes.

as_mean = df["units"].fillna(df["units"].mean())
print(as_mean.count())
print(as_mean.mean())
print(as_mean.std())
Left emptyFilled with mean
Count1416
Mean5.28575.2857

The spread fell about 7%. The two new values sit exactly on the average, so the data looks more consistent than what was recorded. Measures built on the spread, such as a standard error, can then look more precise than they are.

A group median, such as one per product, uses more of what you know. It is still an estimate. Keep a flag so you can tell filled values apart.

out = df.copy()
out["is_units_filled"] = out["units"].isna()
by_product = out.groupby("product")["units"]
out["units"] = out["units"].fillna(by_product.transform("median"))
print(out.loc[out["is_units_filled"], ["order_id", "units"]])

6Fill from something that knowsLookups, and when ffill goes wrong›

ffill copies the previous row down. bfill copies the next row up. Both use row order, so sort first.

d = df.sort_values("order_date").copy()
d["region_ffill"] = d["region"].ffill()
d["region_bfill"] = d["region"].bfill()
cols = ["order_id", "region", "region_ffill", "region_bfill"]
print(d.loc[d["order_id"].between(1013, 1015), cols])
Orderregionffillbfill
1013EastEastEast
1014emptyEastSouth
1015SouthSouthSouth

Both guesses are wrong. Order 1014 belongs to Dana Reyes, and each of her other orders is North.

Look up the region from the rep

known = df.dropna(subset=["region"]).drop_duplicates("rep")
rep_region = known.set_index("rep")["region"]
region = df["region"].fillna(df["rep"].map(rep_region))
print(region[df["region"].isna()])

This prints North. Use it only if the owner of the data confirms that each rep has one region.

Order 1005 has no unit price. Every other Desk is 220, so fill the price and rebuild revenue.

fixed = df.copy()
price = fixed.groupby("product")["unit_price"].transform("median")
fixed["unit_price"] = fixed["unit_price"].fillna(price)
fixed["revenue"] = fixed["revenue"].fillna(
    fixed["units"] * fixed["unit_price"])
print(fixed["revenue"].count(), fixed["revenue"].sum())

Revenue now covers 14 rows and totals 8,810. Two orders still have no units. Check that prices did not change over time before you trust this.

ffill fits values that stay in effect until changed, such as a status. ffill(limit=1) fills at most one hole in a run. For several customers or machines, use df.groupby("id")["value"].ffill() (with your own column names) so one group does not fill another.

fillna(method="ffill") raises an error in pandas 3. Call ffill().

In forecasting, bfill copies a later value into an earlier row. A model then sees information it would not have had.

7Find hidden missing valuesisna() cannot see a -1›

Some systems write a stand-in such as -1 or 999 for unknown. pandas reads it as a real number. This code makes that situation on a copy.

marked = df["units"].fillna(-1)
print(marked.isna().sum())
print(marked.mean())
print(marked.min(), marked.max())
Stored as -1Stored as empty
Holes found02
Mean4.505.29
Minimum-12

Check the lowest and highest value of each number column and ask whether both are possible. df.describe() and value_counts() help. A stand-in such as 0 can look normal, so also ask the data owner.

Turn the stand-in into a real hole

marked = df["units"].fillna(-1)
clean = marked.replace(-1, np.nan)
print(clean.isna().sum(), clean.mean())

Or do it while loading

sample = io.StringIO("order_id,units\n1,-1\n2,999\n3,5\n")
loaded = pd.read_csv(sample, na_values={"units": [-1, 999]})
print(loaded)

Naming the column in na_values leaves the same numbers in other columns alone. See read_csv.

Quick check

isna().sum() returns 0. What can you conclude?

Also useful

✎Report what you didOne sentence to put beside the number›

Ask why each value is missing. A quantity skipped at random and a quantity missing because the order was canceled need different handling.

units = df["units"]
print(f"Average order quantity is {units.mean():.2f} units, "
      f"from {units.count()} of {len(df)} orders. "
      f"{units.isna().sum()} orders have no quantity.")

It prints: Average order quantity is 5.29 units, from 14 of 16 orders. 2 orders have no quantity.

!Edge casesNaN, whole numbers, NA text and merges›
CaseWhat to do
np.nan == np.nanIt is False. Use isna() or notna().
Whole numbers turn into decimalsA hole makes this column float64. Use astype("Int64") to keep whole numbers.
Empty text ""It counts as a value. NaN does not.
The text NAread_csv reads it as missing by default. If it is a real code, see keep_default_na.
Empty merge keyspandas matches them to each other, which can multiply rows.
print(np.nan == np.nan)
print(len(df[df["region"] == np.nan]), df["region"].isna().sum())
print(df["units"].astype("Int64").tail(4))

text = pd.Series(["a", np.nan, "b"])
print(text.count(), text.fillna("").count())

This merge has 2 empty keys on each side. It returns 5 rows: 1 match for x and 4 for the empty keys.

left = pd.DataFrame({"k": ["x", np.nan, np.nan], "a": [1, 2, 3]})
right = pd.DataFrame({"k": ["x", np.nan, np.nan], "b": [4, 5, 6]})
print(left.merge(right, on="k"))

Keep the text NA, still read empty cells as missing

sample = io.StringIO("country_code,units\nNA,5\nUS,3\n")
codes = pd.read_csv(sample, keep_default_na=False, na_values=[""])
print(codes)
