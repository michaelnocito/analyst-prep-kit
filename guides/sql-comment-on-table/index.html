COMMENT ON TABLE

By Michael Nocito, implementation analyst · Updated November 27, 2026

COMMENT ON TABLE saves a description inside the database, attached to the table, so the next person can read it there.

Looking for --, the comment that stops a line from running? Read how to comment in SQL.

The steps

1Decide what to writeSay what the name cannot›

Start with what one row is. The name orders suggests one row per order. Count and see.

SELECT COUNT(*)                 AS row_count,
       COUNT(DISTINCT order_id) AS order_count
FROM orders;
row_countorder_count
32

Three rows, two orders: one row is an order line. That is the table comment.

Then add what a reader cannot guess:

  • Source and timing. "Loaded nightly from billing."
  • Codes and flags. List the values and what they mean.
  • Known problems. "Rows before 2023 have no region."

A comment such as "The orders table" repeats the name and tells the reader nothing new. For a longer format, see commenting SQL so it teaches and documenting data limitations.

2PostgreSQL and OracleCOMMENT ON TABLE and COMMENT ON COLUMN›

The two statements for adding a comment look the same in both.

COMMENT ON TABLE orders IS
  'One row per order line, not per order.';

COMMENT ON COLUMN orders.order_status IS
  'Values: new, paid, shipped, refunded.';
  • Each table or column holds one comment. Running the statement again replaces the text.
  • Double an apostrophe inside the text: 'It''s one row per line.'

Remove a table comment in PostgreSQL

COMMENT ON TABLE orders IS NULL;

Remove a table comment in Oracle

COMMENT ON TABLE orders IS '';

Who can comment, and views

  • PostgreSQL: the table owner (or a role with the owner's rights) or a superuser. For a view, use COMMENT ON VIEW.
  • Oracle: the owner, or a user with the COMMENT ANY TABLE privilege. COMMENT ON TABLE also works on a view.
In PostgreSQL, any user connected to the database can read comments. Do not put passwords or private details in them.
Quick check

You run COMMENT ON TABLE twice on one table with different text. What is stored?

3MySQLA COMMENT clause in CREATE or ALTER›

MySQL has no COMMENT ON statement. The comment is part of the table or column definition.

On a new table. If you made the practice table, run DROP TABLE orders; first.

CREATE TABLE orders (
  order_line_id INT PRIMARY KEY
    COMMENT 'Order line ID, not order ID',
  order_id      INT NOT NULL,
  order_status  VARCHAR(20) DEFAULT 'new' NOT NULL
    COMMENT 'new, paid, shipped, refunded'
) COMMENT = 'One row per order line, not per order.';

Add or change a table comment

ALTER TABLE orders
  COMMENT = 'One row per order line, not per order.';

Add or change a column comment

ALTER TABLE orders
  MODIFY COLUMN order_status
  VARCHAR(20) DEFAULT 'new' NOT NULL
  COMMENT 'new, paid, shipped, refunded';
MODIFY replaces the column definition. If you write only the type and comment here, the column loses NOT NULL and its default. Run SHOW CREATE TABLE orders; and copy the full column definition first. This includes AUTO_INCREMENT.

Remove a table comment

ALTER TABLE orders COMMENT = '';

To remove a column comment, run MODIFY COLUMN with the full definition and no COMMENT.

LimitCharacters
Table comment2,048
Column comment1,024

In strict SQL mode (the MySQL 8 default) a longer comment is an error. Without strict mode you get a warning instead.

4SQL ServerExtended properties named MS_Description›

SQL Server has no COMMENT ON statement. You attach an extended property, a name and a value. Management Studio and many tools look for the name MS_Description. Change dbo if your table is in another schema.

Add a table description

EXEC sys.sp_addextendedproperty
  @name = N'MS_Description',
  @value = N'One row per order line, not per order.',
  @level0type = N'SCHEMA', @level0name = N'dbo',
  @level1type = N'TABLE',  @level1name = N'orders';

Add a column description

EXEC sys.sp_addextendedproperty
  @name = N'MS_Description',
  @value = N'Values: new, paid, shipped, refunded.',
  @level0type = N'SCHEMA', @level0name = N'dbo',
  @level1type = N'TABLE',  @level1name = N'orders',
  @level2type = N'COLUMN', @level2name = N'order_status';

Change a table description

EXEC sys.sp_updateextendedproperty
  @name = N'MS_Description',
  @value = N'One row per order line.',
  @level0type = N'SCHEMA', @level0name = N'dbo',
  @level1type = N'TABLE',  @level1name = N'orders';

Remove a table description

EXEC sys.sp_dropextendedproperty
  @name = N'MS_Description',
  @level0type = N'SCHEMA', @level0name = N'dbo',
  @level1type = N'TABLE',  @level1name = N'orders';
  • sp_addextendedproperty raises an error if that property already exists. Use the update procedure.
  • You need to own the object or have ALTER or CONTROL permission on it.
  • A value can be up to 7,500 bytes.
Quick check

Adding a description fails because the property already exists. What do you run?

5SQLiteNo comment feature, one workaround›

SQLite has no COMMENT ON and no stored table descriptions. It does keep the text of your CREATE TABLE statement, so put -- comments inside it.

If you made the practice table, run DROP TABLE orders; first.

CREATE TABLE orders ( -- One row per order line.
  order_line_id INT PRIMARY KEY,
  order_id      INT NOT NULL,
  order_status  VARCHAR(20) DEFAULT 'new' NOT NULL
    -- new, paid, shipped, refunded
);

Read it back

SELECT sql
FROM sqlite_schema
WHERE type = 'table' AND name = 'orders';

The result is the statement with your comments. sqlite_schema needs SQLite 3.33 or later. Older versions use sqlite_master.

A comment written above CREATE TABLE is not saved. Tools generally will not show these notes as descriptions, so also keep them in a file next to your schema script.

6Read one table backCheck what is stored›

Run the block for your database after you add the comments.

PostgreSQL: table comment

SELECT obj_description('orders'::regclass, 'pg_class')
         AS table_comment;

In the psql tool, \dt+ orders shows the table comment and \d+ orders shows column comments.

Oracle (unquoted names are stored in capitals)

SELECT comments
FROM user_tab_comments
WHERE table_name = 'ORDERS';

SELECT column_name, comments
FROM user_col_comments
WHERE table_name = 'ORDERS';

MySQL

SHOW CREATE TABLE orders;

SHOW FULL COLUMNS FROM orders;

SQL Server: table description

SELECT name, value
FROM sys.fn_listextendedproperty(
  N'MS_Description',
  N'SCHEMA', N'dbo',
  N'TABLE',  N'orders',
  NULL, NULL);
7Build a data dictionaryAll comments in one query, plus the gaps›

A data dictionary lists tables, columns and what they mean. Your database can produce a starting one.

PostgreSQL (change public to your schema)

SELECT c.relname AS table_name,
       a.attname AS column_name,
       obj_description(c.oid, 'pg_class') AS table_comment,
       col_description(c.oid, a.attnum)   AS column_comment
FROM pg_class c
JOIN pg_namespace n ON n.oid = c.relnamespace
JOIN pg_attribute a ON a.attrelid = c.oid
WHERE n.nspname = 'public'
  AND c.relkind IN ('r', 'p')
  AND a.attnum > 0
  AND NOT a.attisdropped
ORDER BY c.relname, a.attnum;

MySQL (current database)

SELECT c.TABLE_NAME, c.COLUMN_NAME,
       t.TABLE_COMMENT, c.COLUMN_COMMENT
FROM information_schema.COLUMNS c
JOIN information_schema.TABLES t
  ON t.TABLE_SCHEMA = c.TABLE_SCHEMA
 AND t.TABLE_NAME = c.TABLE_NAME
WHERE c.TABLE_SCHEMA = DATABASE()
  AND t.TABLE_TYPE = 'BASE TABLE'
ORDER BY c.TABLE_NAME, c.ORDINAL_POSITION;

Oracle (your own tables)

SELECT c.table_name, c.column_name,
       t.comments AS table_comment,
       c.comments AS column_comment
FROM user_col_comments c
JOIN user_tab_comments t ON t.table_name = c.table_name
WHERE t.table_type = 'TABLE'
ORDER BY c.table_name, c.column_name;

SQL Server (described tables and columns; a blank column name means the table)

SELECT t.name   AS table_name,
       c.name   AS column_name,
       ep.value AS description
FROM sys.tables AS t
JOIN sys.extended_properties AS ep
  ON ep.major_id = t.object_id
 AND ep.class = 1
 AND ep.name = N'MS_Description'
LEFT JOIN sys.columns AS c
  ON c.object_id = ep.major_id
 AND c.column_id = ep.minor_id
ORDER BY t.name, ep.minor_id;

Find tables with no comment

Each query returns your to-do list. No rows means no gaps in the tables it checked.

PostgreSQL

SELECT c.relname AS table_name
FROM pg_class c
JOIN pg_namespace n ON n.oid = c.relnamespace
WHERE n.nspname = 'public'
  AND c.relkind IN ('r', 'p')
  AND obj_description(c.oid, 'pg_class') IS NULL;

MySQL

SELECT TABLE_NAME
FROM information_schema.TABLES
WHERE TABLE_SCHEMA = DATABASE()
  AND TABLE_TYPE = 'BASE TABLE'
  AND TABLE_COMMENT = '';

Oracle

SELECT table_name
FROM user_tab_comments
WHERE table_type = 'TABLE'
  AND comments IS NULL;

SQL Server

SELECT t.name AS table_name
FROM sys.tables AS t
WHERE NOT EXISTS (
  SELECT 1
  FROM sys.extended_properties AS ep
  WHERE ep.class = 1
    AND ep.major_id = t.object_id
    AND ep.minor_id = 0
    AND ep.name = N'MS_Description');
