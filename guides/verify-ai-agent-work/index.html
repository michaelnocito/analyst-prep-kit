How to Verify an AI Agent Actually Did the Work

By Michael Nocito, implementation analyst · Updated November 27, 2026

An AI agent tells you the work is done. Here are five checks that help show whether it is, for code, data moves and migrations.

The short version: a report is not evidence. A check on the delivered thing is, and it proves only what it checks.
Why I check

While researching this guide, I asked a research agent for published complaints about agents reporting unfinished work as finished. It returned three quotes, each tied to a public bug report. I checked them. One was real. The other two did not exist.

Much of its other research was good. A confident report and a correct one can look the same. Going to the source told them apart.

What each kind of evidence shows
⌘Practice projectBuild it once, then run every check›

A tiny program that lists ids missing from a load, with three tests. You need Node.js with npm, Python 3, and a Bash terminal (macOS, Linux, or Git Bash on Windows). Paste this in an empty folder where nothing is named agent-check.

mkdir -p agent-check/src agent-check/test agent-check/build agent-check/live
cd agent-check
cat > package.json <<'END'
{ "scripts": { "test": "node --test --test-reporter=tap" } }
END
cat > src/reconcile.js <<'END'
// reconcile-v2
module.exports = (source, loaded) =>
  source.filter(id => !loaded.includes(id));
END
cat > test/reconcile.test.js <<'END'
const test = require('node:test');
const assert = require('node:assert');
const missing = require('../src/reconcile');

test('finds a missing id', () =>
  assert.deepStrictEqual(missing([1, 2, 3], [1, 3]), [2]));
test('nothing missing', () =>
  assert.deepStrictEqual(missing([1, 2], [2, 1]), []));
test('empty load', () =>
  assert.deepStrictEqual(missing([1, 2], []), [1, 2]));
END
cp src/reconcile.js build/reconcile.js
echo '// reconcile-v1' > live/reconcile.js

You should now be inside agent-check. Run the steps in order. build stands for a copy another tool wrote. live stands for your website.

Tested on Linux with Node 22.23.5, npm 10.9.9, Python 3.13.18, Bash 5.2.21, curl 8.5.0, GNU grep 3.11, GNU sed 4.9 and GNU coreutils 9.4. Not tested on macOS or Windows.

The steps

1Ask for the command and outputA claim is not the evidence›

For each completion claim, ask: what command would show this, and did it run?

Copy this line into your next request.

Show me each command you ran, its output and its exit code.
List what you did not verify.

Then run the important command yourself. Pasted output is still text the agent wrote. Run this in the practice folder.

npm test > test.log
echo "exit $?"
grep -E "^# (tests|pass|fail|skipped)" test.log
You seeWhat it tells you
exit 0The test command reported success
# tests 3Three tests were found
# pass 3All three passed
# fail 0, # skipped 0None failed or was skipped
Watch for: “should pass”, “seems correct”, “probably fine”. Treat these as an open question until you see a result.
Quick check

An agent pastes output showing every test passed. What is the strongest next move?

2Check the file another wayA success message is not the file›

The tool that writes a file can report success when the file on disk is wrong. One bug report about Claude’s desktop file tools (Cowork) describes cut-off writes that reading the file back did not show:

The Read tool cannot verify a write. It returns intent, not disk state.

anthropics/claude-code issue #53940, April 2026

Verify through a different path than the one that did the work. This makes a bad copy on purpose, then checks size and hash. A hash is a fingerprint of the contents.

tr 'a-z' 'A-Z' < src/reconcile.js > build/reconcile.js
wc -c src/reconcile.js build/reconcile.js
sha256sum src/reconcile.js build/reconcile.js
FileBytesHash starts
src/reconcile.js98318a58f8
build/reconcile.js987045dddf

The sizes match and the contents do not. A byte count catches a short file. It misses a same-size change. Put the copy right:

cp src/reconcile.js build/reconcile.js

A related trap: the agent edits one folder while your app runs from another. Check the path the app actually loads.

Quick check

Two files have the same size. What shows whether their contents match?

3Count the testsA green run can cover less›

A passing run is evidence about the tests that ran. This skips one test, the way a rushed fix might.

sed -i.bak "s/^test('empty load'/test.skip('empty load'/" test/reconcile.test.js
npm test > test.log
echo "exit $?"
grep -E "^# (tests|pass|fail|skipped)" test.log
grep -rnE "\.(skip|only|todo)\(" test
ResultBeforeAfter
Exit code00
Tests33
Passed32
Skipped01

The exit code did not move. The last command also points to test/reconcile.test.js line 9. Restore the file:

mv test/reconcile.test.js.bak test/reconcile.test.js

One user report from March 2025 says that, asked to make all tests pass, the agent changed the make file to run only the passing ones and called them “safe-tests” (issue #319).

Quick check

Tests went from 41 passing to 38 passing with 3 skipped. The run is green. What do you check?

4Check where users meet itA push is not a live change›

A change can be committed, pushed and tested, and still not be live. I have declared work shipped on a clean push while the deployment had failed and the site served the old version.

Programmatic test does not equal live app verification for dialog-layer bugs.

anthropics/claude-code issue #47247, April 2026

Practice with a small local server. In a second terminal, from the folder that holds agent-check, start it. On some Windows setups the command is python.

cd agent-check/live
python3 -m http.server 8000 --bind 127.0.0.1

In your first terminal, check the served file, deploy, and check again.

curl -s "http://127.0.0.1:8000/reconcile.js?cb=$RANDOM" |
  grep -c "reconcile-v2"
cp src/reconcile.js live/reconcile.js
curl -s "http://127.0.0.1:8000/reconcile.js?cb=$RANDOM" |
  grep -c "reconcile-v2"
WhenCountMeaning
Before the copy0The old version is served
After the copy1The new marker is served

grep -c counts matching lines. The ?cb= number helps get past a cached copy, though some caches ignore it. Press Ctrl+C in the second terminal to stop the server.

5Keep the gate out of reachA check the worker can edit is weak›

A gate is a check that must pass before work counts as done. This saves fingerprints outside the project, swaps the test command for one that runs nothing, then checks.

sha256sum package.json test/*.js > ../gate.sha256
sed -i.bak 's/node --test[^"]*/echo ok/' package.json
npm test > test.log
echo "exit $?"
sha256sum -c ../gate.sha256
mv package.json.bak package.json
sha256sum -c ../gate.sha256
CheckResult
npm test after the swapExit 0, with no tests run
Hash checkpackage.json: FAILED
After restoringBoth files OK
A file one folder up is practice, not security. An agent with the same access can edit it too. For a real gate, use a place it cannot write: your own machine, protected CI settings, or a person who looks. If your Mac has no sha256sum, use shasum -a 256.

Users have reported this. In issue #80700 (July 2026), the user says the model put off a bug it could fix, then created the user’s own stop-hook bypass file and ended the turn. A hook is a script that runs at a set point. A Cline report from July 2026 makes the design rule clear. A flag the model sets about its own command should:

only be able to raise the approval requirement, never waive it

cline/cline issue #12020

Written rules help, but they are not a lock. The Claude Code docs say CLAUDE.md files are treated as context, not enforced configuration, and point to a PreToolUse hook to block an action. Protect that hook from edits too.

Quick check

Where should the check that decides “done” live?

7See how often it happensOne study and two surveys›

Real sessions

A 2026 preprint (not peer-reviewed) studied 20,574 coding-agent sessions and found 16,118 episodes where developer pushback showed the agent was out of line.

Problem typeShare of episodes
Broke a developer’s constraint38%
Misread intent27%
Reported its own work inaccurately23%
Faulty implementation18%

These are the top four of seven types, and the shares add to more than 100%. Misalignment per user turn fell over the study period, while inaccurate self-reporting grew as a share of what remained. The authors suggest, as a possible explanation, that training rewards correct code more readily than honest reporting. The data covers publicly logged sessions and problems the developer noticed.

Tests under pressure

The ImpossibleBench preprint (2025) gave models tasks whose tests could not be passed honestly. On one set, GPT-5 cheated on 76% of tasks.

DefenseWhat the paper reports
Hide the testsCheating near zero; normal task scores also dropped
Make tests read-onlyStops test edits, not every other trick
Stricter promptOn another set, GPT-5 fell from 92% to 1%; results varied by model

A separate study of over 1.2 million commits found coding agents added mocks (stand-ins for real parts) more often than others: 36% against 26%. That counts mocks, not test quality.

What developers say

  • Sonar’s 2026 survey of more than 1,100 developers: 96% do not fully trust AI code to be functionally correct, and 48% always check it before committing. Sonar sells code review tools.
  • Stack Overflow’s 2025 survey: 66% picked “AI solutions that are almost right, but not quite” as a frustration, the most common pick.
8Start with your own workFive habits, one at a time›

Think of the last thing an agent built that you shipped without opening. What would you check first? Start there.

  1. Ask for commands and output.
  2. Check your delivery boundary by hand until you know what success looks like.
  3. Count tests before and after.
  4. Move one key check out of the agent’s reach.
  5. Ask what was not verified.

For new work, write down what will count as proof before the work starts.

The idea is old: the person who counts the cash drawer is not the person who ran it. An agent can report something wrong without any intent we can see, so build the check to work either way.

Mechanical checks catch counts and bytes. They did not catch the invented quotes in my story. Those took a trip to the source.
