Load a CSV Into a Database Safely

By Michael Nocito, implementation analyst · Updated November 27, 2026

Load every column as text into a staging table, find the bad values, then copy into a typed table. The raw rows stay available if a conversion goes wrong.

Practice file

A made-up export with problems on purpose: IDs with leading zeros, mixed formats, an impossible date and a total row.

2Load into a staging tableEvery column TEXT›

A staging table holds the file as it arrived. Put orders.csv in a folder, open a terminal there and run sqlite3 practice.db. Then paste:

DROP TABLE IF EXISTS orders_raw;
CREATE TABLE orders_raw (
  order_id   TEXT,
  customer   TEXT,
  order_date TEXT,
  amount     TEXT,
  status     TEXT
);

.mode csv
.import --skip 1 orders.csv orders_raw
.mode box

SELECT COUNT(*) AS raw_rows FROM orders_raw;
raw_rows
7

The file has 8 lines: 1 header and 7 data rows. --skip 1 leaves the header out because the table already exists.

If the table does not exist, .import --csv creates one from the header row with text columns. Creating it yourself makes the columns clear.

3Find bad valuesDates and amounts, before casting›

Dates that are not real YYYY-MM-DD dates

SELECT order_id, order_date
FROM orders_raw
WHERE DATE(order_date) IS NOT order_date;
order_idorder_date
0004303/05/2026
000452026-02-30
TOTAL

Comparing with DATE() catches both the wrong format and February 30. A pattern such as LIKE '____-__-__' would let February 30 through. In the SQLite version tested here, DATE('2026-02-30') returned 2026-03-02.

Amounts that are blank or not plain numbers

SELECT order_id, amount
FROM orders_raw
WHERE TRIM(amount) = ''
   OR REPLACE(REPLACE(TRIM(amount), '$', ''), ',', '')
      GLOB '*[^0-9.]*';
order_idamount
00044N/A
00046
A failed cast may not be empty. In SQLite, CAST('N/A' AS REAL) returns 0.0, and so does CAST('$1,240' AS REAL). Counting NULLs after a plain cast misses both.

This is a simple check for this file. It rejects negative amounts and would let a value such as 1.2.3 through, so adjust it to your data. $ and the thousands comma are removed first.

4Copy into a clean tableConvert on purpose›

Each change is written in the query. Bad dates and amounts become NULL instead of a made-up value. The total row is left out.

DROP TABLE IF EXISTS orders;
CREATE TABLE orders (
  order_id   TEXT NOT NULL PRIMARY KEY,
  customer   TEXT,
  order_date TEXT,
  amount     REAL,
  status     TEXT
);

INSERT INTO orders
SELECT
  TRIM(order_id),
  TRIM(customer),
  CASE WHEN DATE(order_date) IS order_date
       THEN order_date END,
  CASE WHEN TRIM(amount) <> ''
        AND REPLACE(REPLACE(TRIM(amount), '$', ''), ',', '')
            NOT GLOB '*[^0-9.]*'
       THEN CAST(REPLACE(REPLACE(TRIM(amount), '$', ''), ',', '')
            AS REAL) END,
  LOWER(TRIM(status))
FROM orders_raw
WHERE order_id <> 'TOTAL';

SELECT * FROM orders;

Names are left out of this table to keep it narrow. SQLite shows NULL as an empty cell. It has no separate date type, so dates are stored as YYYY-MM-DD text.

03/05/2026 could mean March 5 or May 3. Ask the file owner, then add a rule. Do not guess.

Keep IDs as TEXT. 00042 stored as a number is 42. See leading zeros on import.

5Check the loadCounts, NULLs, a total and a known ID›
SELECT
  COUNT(*)                     AS row_count,
  COUNT(*) - COUNT(order_date) AS null_dates,
  COUNT(*) - COUNT(amount)     AS null_amounts,
  ROUND(SUM(amount), 2)        AS amount_total
FROM orders;

SELECT * FROM orders WHERE order_id = '00042';
CheckResultWhy it matches
row_count67 raw rows minus TOTAL
null_dates200043 and 00045
null_amounts200044 and 00046
amount_total1497.49Same as the TOTAL row
ID 000421 rowZeros kept

The total is a useful independent check. A match does not prove every value is right, so also compare a few rows with the source. More: reconciliation and data quality checks.

Counting file lines (wc -l on Mac or Linux) can mislead when a quoted value contains a line break, or when the last line has no ending newline.

6Use another toolDuckDB, PostgreSQL, pandas, DB Browser›

The idea stays the same: bring in text, then convert.

DuckDB

CREATE TABLE orders_raw AS
SELECT * FROM read_csv('orders.csv', all_varchar = true);

DuckDB 2.0.1 kept the leading zeros in this test even without all_varchar. Setting it avoids relying on detection.

PostgreSQL, in psql

CREATE TABLE orders_raw (
  order_id TEXT, customer TEXT, order_date TEXT,
  amount TEXT, status TEXT
);
\copy orders_raw FROM 'orders.csv' WITH (FORMAT csv, HEADER true)

\copy reads a file on your computer. COPY with a file name reads from the database server.

Python with pandas

import sqlite3
import pandas as pd

df = pd.read_csv("orders.csv", dtype=str, keep_default_na=False)
con = sqlite3.connect("practice.db")
df.to_sql("orders_raw", con, if_exists="replace", index=False)
print(len(df))
con.close()
Without dtype=str, pandas reads IDs such as 00042 as the number 42. if_exists="replace" drops an existing orders_raw table.

7Make repeat loads safeA script and a log›
  1. Save the commands in a script file, so each load runs the same way.
  2. Keep the original files unchanged, with the date in the folder or file name.
  3. Add the source file name and load date to the loaded rows.
  4. Load into staging and run the checks before you replace or append to the clean table.
  5. Record the row count and total of each load in a small log table.

Importing into a table that still holds the last load adds the rows again. The DROP TABLE IF EXISTS lines prevent that here.
