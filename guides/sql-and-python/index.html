How SQL and Python Work Together in Data Analysis

By Michael Nocito, implementation analyst · Updated November 27, 2026

Why two tools if both work with data? Run one small relay and watch each hand off to the other.

The short answer
SQLPython
Asks questions of data in a databaseConnects the database to everything around it
Filter, join, group, totalFetch, automate, model, chart

A rule of thumb. The two overlap.

Pick by location: data already in a database, start with SQL. Data on the web or scattered in files, start with Python.
Practice data · made-up artists and plays

Run this first. Then run the other boxes in order, in the same Python session or one file. No download or API key needed.

The steps

1SQL asks the first questionWho has 3 or more charted songs?›

SQL asks questions of tables: filter, join, group, summarize. Here the tables are already loaded, so SQL starts.

roster_query = """
SELECT artist, COUNT(*) AS songs_charted
FROM chart_songs
GROUP BY artist
HAVING COUNT(*) >= 3   -- SQL comment: keep busy artists
ORDER BY artist
"""
# Python comment: run the SQL, keep the names
roster = [row[0] for row in conn.execute(roster_query)]
print(roster)
Result
['Juno Vale', 'Maple Static']

HAVING filters groups. The Low Fields has one charted song, so it drops out.

The SQL sits inside a Python string. sqlite3 comes with the standard Python installers and carries the query to the database.

SQL comments start with --. Python comments start with #.

2Python goes and gets data7 tracks from saved API replies›

An API is a web address that answers requests with data. Standard SQL has no command for calling one, so Python is the usual choice.

Build the request address (nothing is sent)

from urllib.parse import urlencode

params = urlencode({
    "method": "artist.gettoptracks",
    "artist": "Juno Vale",
    "api_key": "YOUR_KEY",
    "format": "json",
    "limit": 50,
})
print("https://ws.audioscrobbler.com/2.0/?" + params)

It prints one long address. With your own Last.fm API key, urllib.request.urlopen(url, timeout=30) sends it. Keep real keys out of code you share.

Read the replies and load a table

def fetch_reply(artist):
    # Practice version: returns saved text, no internet needed
    return saved_replies[artist]

conn.execute("DROP TABLE IF EXISTS api_tracks")
conn.execute("""CREATE TABLE api_tracks
    (artist TEXT, track TEXT, playcount INTEGER, listeners INTEGER)""")

for artist in roster:
    data = json.loads(fetch_reply(artist))
    for t in data["toptracks"]["track"]:
        conn.execute(
            "INSERT INTO api_tracks VALUES (?, ?, ?, ?)",
            (artist, t["name"], int(t["playcount"]), int(t["listeners"])),
        )
conn.commit()
print(conn.execute("SELECT COUNT(*) FROM api_tracks").fetchone()[0])
ResultMeaning
7Tracks now in api_tracks

The replies hold numbers as text, so int() converts them. The ? marks pass values safely into SQL.

With a real API, pause between requests and read its terms. One failed request should be logged, not end the whole run.

3SQL finds the answer2 loved songs with no chart match›

Both tables are in the database now. SQL joins them and keeps the tracks with no chart match.

gem_query = """
SELECT a.artist,
       a.track,
       ROUND(a.playcount * 1.0 / a.listeners, 1) AS plays_per_listener
FROM api_tracks AS a
LEFT JOIN chart_songs AS c
  ON LOWER(a.artist) = LOWER(c.artist)
 AND LOWER(a.track) = LOWER(c.title)
WHERE c.title IS NULL
  AND a.listeners >= 1000
  AND a.playcount * 1.0 / a.listeners >= 6
ORDER BY plays_per_listener DESC
"""
gems = conn.execute(gem_query).fetchall()
for row in gems:
    print(row)
artisttrackPlays per listener
Juno ValeNight Ferry8.2
Maple StaticBack Stairs7.0
  • LEFT JOIN with c.title IS NULL keeps tracks that found no partner.
  • LOWER lets orbit match Orbit. SQLite's built-in version changes only A to Z.
  • * 1.0 matters: SQLite divides two integers as an integer.
  • The 1,000 listener floor removes Tiny Demo: 15 plays per listener, but only 60 people.

4Python hands over the resultA CSV file someone can open›

The answer is small now. Python writes it to a file.

import csv

with open("gems.csv", "w", newline="", encoding="utf-8") as f:
    writer = csv.writer(f)
    writer.writerow(["artist", "track", "plays_per_listener"])
    writer.writerows(gems)

print(len(gems), "rows written to gems.csv")
Result
2 rows written to gems.csv

Optional: the same handoff with pandas

If pandas is installed, one call turns a query into a table you can chart or reshape.

import pandas as pd

gems_df = pd.read_sql_query(gem_query, conn)
print(gems_df.to_string(index=False))

5A real project with both toolsFinding songs that never charted›

My music hidden gems project asks which tracks by artists with a chart history get replayed a lot but have no chart match. It runs the same relay.

ToolWhat happenedCount
DataWeekly Billboard Hot 100 rows in the database, August 1958 to July 11, 2026354,500
SQLArtists with 5 or more charted songs, using HAVING1,570
PythonTracks fetched from Last.fm, up to 50 per artist, saved as a CSV78,335
SQLTracks with 1,000+ listeners and 6+ plays per listener13,090
SQLSongs with no chart match, after a LEFT JOIN and grouping repeats7,574

The Python is one fetch script: it reads the artist list with a SQL query, pauses 0.25 seconds between requests, and records failed artists. The SQL file holds the queries. The project also has later Python scripts for extra details.

The Hot 100 combines sales, streaming and radio airplay. A missing chart match does not show that radio ignored a song, and a spelling difference can also cause one.

6Which tool to reach for7 common jobs›
You need toStart withWhy
Filter, join or total database tablesSQLThe work happens where the data is
Get data from a web APIPythonIt has libraries for web requests
Combine many files in a folderPythonIt can loop over files and fix each one
Define a metric others can reviewSQLA saved query shows the rule

These are starting points, not limits. Some databases reach further: DuckDB can query CSV files in a folder or at a web address. pandas can also filter, join and group.

When the data already lives in a database, filter and total it there. Bring Python the smaller result.

7Which to learn firstMy suggestion: SQL›

I suggest SQL first for analyst work:

  • It is a narrower language than Python, built for asking questions of data.
  • SELECT, WHERE, JOIN and GROUP BY answer many everyday questions.
  • Python is easier to aim once you know what you need it for, such as data that is not in a database yet.

Start with Python instead if your work today is mostly files, web data or repeated cleanup. Check the job postings you care about for what they ask.
