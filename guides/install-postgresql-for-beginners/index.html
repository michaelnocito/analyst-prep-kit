Install PostgreSQL for Beginners

By Michael Nocito, implementation analyst · Updated November 27, 2026

Install PostgreSQL, connect to it, make your own database and load a CSV. The big change from SQLite: you connect to a program that is running instead of opening a file.

PostgreSQL 19 was released on November 19, 2026. Database commands on this page were tested with PostgreSQL 16.15 on Linux. The Windows and Mac install notes come from the download pages and documentation, and were not run.

The steps

1Decide if you need itSQLite may be enough›

Core SQL such as SELECT, JOIN, GROUP BY and window functions is available in both SQLite and PostgreSQL. Install PostgreSQL when one of these is true:

  • A job posting or take-home test names PostgreSQL
  • You need to practice against a database server: users, permissions, ports
  • Several people or programs need to share and change the same data

If you only have login details for a database someone else runs, you need a client tool such as pgAdmin or psql, not your own server.

If none apply, SQLite is quicker to set up. Compare in Which SQL database to install.

Differences to expect

CasePostgreSQLSQLite
'abc' = 'ABC'FalseFalse
'abc' LIKE 'ABC'False (ILIKE ignores case)True
A column missing from GROUP BYError hereRuns, picks one row's value
"East" in double quotesReads it as a column nameCan read it as text
N/A into a number columnErrorStored as text

Tested with PostgreSQL 16.15 and SQLite 3.53.1, on normal (not STRICT) SQLite tables. Date functions differ too.

2Install PostgreSQLPick a download for your system›

Start at postgresql.org/download and pick your system. Choose a stable release, not a beta or release candidate.

Windows

The page links to the interactive installer by EDB. It includes:

PartWhat it is
PostgreSQL ServerThe database, running as a Windows service
pgAdminA graphical tool for queries and tables
Command Line Toolspsql and related commands
Stack BuilderOptional extra drivers and tools

The installer asks for a password for the postgres user and a port. Save the password in a password manager. The default port is 5432; keep it unless something else uses it. You can skip Stack Builder for this guide.

PostgreSQL 19 is new. On November 27, 2026 the support table on the Windows download page still ended at 18. If the installer list does not show 19, choose 18. Nothing on this page needs 19.

Mac

The Mac download page lists several options, including the EDB installer and Postgres.app. Homebrew is another route. User names and passwords can differ between them, so follow the notes for the one you pick.

3Learn the connection factsHost, port, database, user›

A client such as psql, pgAdmin or Python needs to know where to connect and who you are.

FactMeaningLocal EDB install
HostWhich computerlocalhost
PortWhich numbered entry on it5432
DatabaseWhich database on the serverpostgres at first
UserWho you arepostgres
PasswordProof of who you areThe one you set

A connection string

postgresql://postgres:YOUR_PASSWORD@localhost:5432/postgres

It reads: type, user, password, host, port, database. A password containing characters such as @ or / must be encoded in this form. Keeping the password out of the string and typing it when asked is simpler.

4Make your own databaseThen test the connection›

Open a terminal in the folder that holds sales.csv, then connect. On Windows you can also open SQL Shell (psql) from the Start menu and press Enter to accept each default.

Terminal

psql -h localhost -p 5432 -U postgres -d postgres

Type your password when asked. Nothing shows while you type. A postgres=# prompt means you are in.

If the terminal cannot find psql on Windows, add the PostgreSQL bin folder to your PATH (often C:\Program Files\PostgreSQL\18\bin, with your version number), or use SQL Shell.

In psql

CREATE DATABASE analytics;
\c analytics
SELECT current_database(), current_user, current_schema();
current_databasecurrent_usercurrent_schema
analyticspostgrespublic

\c switches database. The postgres database is there as a default place to connect. A separate database keeps your practice work apart. If analytics already exists, CREATE DATABASE reports an error; just connect to it.

A schema is a named group of tables inside a database. By default new tables go in public, so sales is also public.sales.

To check the server version:

In psql

SELECT version();

Prefer pgAdmin? Open it, connect with the same facts and run SQL in its Query Tool. Commands that start with a backslash work in psql, not in the Query Tool.

5Load a CSVCreate the table, then copy›

Stay connected to analytics. \copy loads into a table that exists, so create it first.

In psql

DROP TABLE IF EXISTS sales;

CREATE TABLE sales (
    order_id   TEXT PRIMARY KEY,
    order_date DATE,
    region     TEXT,
    amount     NUMERIC(10,2)
);

DROP TABLE deletes an existing table named sales. order_id is text so its leading zeros stay.

In psql: this one fails on purpose

\copy sales FROM 'sales.csv' WITH (FORMAT csv, HEADER true)

The error names the problem: invalid input syntax for type numeric: "N/A", at line 6, column amount. In this test the table stayed empty: the good rows were not kept. Tell PostgreSQL that N/A means no value:

In psql

\copy sales FROM 'sales.csv' WITH (FORMAT csv, HEADER true, NULL 'N/A')

In psql

SELECT region,
       COUNT(*)    AS orders,
       SUM(amount) AS revenue
FROM sales
GROUP BY region
ORDER BY region;
regionordersrevenue
East2167.75
North1310.00
West280.00

West has 2 orders but only one amount. SUM skips the NULL. With NULL 'N/A', an empty amount no longer counts as no value. In a test, an empty amount then caused an error.

\copy reads a file on your computer. COPY with a file name reads from the server's computer. If psql cannot find the file, use its full path, with forward slashes on Windows. Running the second load again fails on the duplicate key.

6Connect from PythonKeep the password out of the file›

Terminal

python -m pip install sqlalchemy "psycopg[binary]" pandas

Python

import os
from getpass import getpass

import pandas as pd
from sqlalchemy import URL, create_engine

url = URL.create(
    "postgresql+psycopg",
    username="postgres",
    password=os.environ.get("PGPASSWORD") or getpass(),
    host="localhost",
    port=5432,
    database="analytics",
)
engine = create_engine(url)

df = pd.read_sql(
    "SELECT COUNT(*) AS row_count, SUM(amount) AS revenue "
    "FROM sales",
    engine,
)
print(df.to_string(index=False))
engine.dispose()
row_countrevenue
5557.75

Run it from a terminal, which asks for the password. URL.create handles special characters in it. Do not type a password into a file you share or commit; see Git for analysts. More: Connect Python to a database.

!Fix connection errorsMessages and causes›
MessageWhat to check
Connection refusedIs the server running? Is the port right? On Windows, look in Services for postgresql
password authentication failedThe user name and password
database "…" does not existThe spelling, or create it first
relation "…" does not existAre you in the right database? Does the name need quotes?
psql is not recognizedAdd the bin folder to PATH, or use SQL Shell
Port 5432 already in useAnother server, often an older PostgreSQL. Stop it, or pick another port and use that number when you connect

PostgreSQL turns unquoted names into lower case. A table created as "Sales" must be written with quotes afterwards. Lower case names without quotes avoid this.

?Reset a forgotten passwordNeeds admin rights on the computer›

This is for a server on your own computer. On a shared server, ask its administrator.

  1. Find pg_hba.conf in the data folder (on Windows, often C:\Program Files\PostgreSQL\18\data). Save a backup copy.
  2. In the two host lines for all databases with addresses 127.0.0.1/32 and ::1/128, change the last word to trust.
  3. Restart the PostgreSQL service.
  4. Connect with psql -h localhost -U postgres and run \password postgres. Enter a new password twice.
  5. Put the backup file back and restart the service again.
  6. Connect with the new password.
While trust is set, people and programs on that computer can connect as any database user without a password. Do steps 5 and 6 right away.

Tested on Linux with a reload in place of a restart. Not tested on Windows or Mac.
